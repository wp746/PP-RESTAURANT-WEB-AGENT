# PP Restaurant Web Studio
## 《餐饮品牌线上门面设计总纲》

**版本**：1.0（基线）  
**适用对象**：餐饮门店品牌网站设计智能体、采集人员、视觉设计师、前端开发、验收人  
**适用范围**：从真实餐饮门店素材包生成手机优先的、可交互的、可部署的品牌线上门面  
**当前阶段**：设计方法与交付规则已确立；不是已经自动部署的生成器或已安装的 Skill  
**案例来源**：本项目「旺角肥肠鸡」从三案测试到 V4 融合式网页的迭代，以及此前《餐饮线上门面设计与动效规范 v1》《文化优先融合设计工作流 v2》。

# 第一章｜项目宗旨与不可变原则

### 1.1 目标定义

用户只需为一家门店提供：基本信息、经营资料、菜单及价格、产品与空间实拍、老板的文字信息和已有品牌资产。系统负责理解品牌、提炼文化、定制视觉、规划交互、组织完整展示、生成真实可运行网页并提供验收材料。

**最终交付是一家店的一套完整网站，而不是同模板的三套换色网页。** 当用户专门要求对比时，可以制作多个独立方向进行探索；但选定后必须整合进一套内部一致的品牌表达。

网站不是菜单截图、不是长海报、不是产品相册，也不是为了展示特效而牺牲操作的动画作品。它必须同时回答顾客四个问题：**这是谁？为什么值得记住？吃什么、怎么选？怎么联系与到店？**

### 1.2 永久优先级

**文化第一 → 视觉第二 → 交互第三 → 展示第四。**

| 顺位 | 职责 | 核心问题 | 成功证据 | 常见失败 |
|---|---|---|---|---|
| 文化 01 | 给品牌以独有逻辑 | 这家店为何如此，而非另一家？ | 品牌主张、产品文化、语气与视觉符号有真实依据 | 堆砌“百年”“匠心”，套用江湖/国潮故事 |
| 视觉 02 | 把文化翻译成感知体验 | 为什么要用这套字体、色彩、摄影与排版？ | 主次分明、适配品类、空间关系准确、原创辨识度 | 黑金通用模板、字体统一、无脑卡片化 |
| 交互 03 | 帮顾客理解与决策 | 哪些操作让顾客更容易选择？ | 口味、搭配、产品、场景、CTA 反馈明确 | 只会动但没有价值、伪按钮、滚动劫持 |
| 展示 04 | 以事实完成信任与转化 | 顾客能否找到真实信息并到店？ | 菜单、价格、环境、联系方式、营业时间可核查 | 地址难找、价格缺失、门店照片不真实 |

> **解释规则**：排序是创意决策的优先顺序，**不是页面章节排列顺序，也不是功能重要性排名**。必须让电话、导航、菜品入口易于找到；不强迫顾客阅读冗长历史才能完成操作。

### 1.3 八条红线（违反任何一条都不可进入正式交付）

1. **不编造企业事实**：创始人、创立年份、店龄、奖项、非遗身份、配方秘传、原料产地、经营理念等，未经核实不得写成事实。
2. **不拿品类历史冒充门店历史**：川渝江湖菜的研究可以解释品类，但不能据此写出某家店的“发展史”。
3. **不冒充实景与实物**：演示合成图、AI 概念图、第三方参考照片必须标记；正式使用须核对真实性、素材授权与食材 DNA。
4. **不千店一面**：不是只换色、文字与照片；每家店重新决定文化母题、构图、字体、视觉节奏、交互和展示逻辑。
5. **不牺牲主体完整性**：真实锅碗盘、关键食材、Logo、门头招牌不得出现无意识裁切或几何拉伸。
6. **不做假功能**：无效电话、导航、团购、企微、会员按钮一律不允许；未接后端的订位/付款不得提示已真实完成。
7. **不以代码存在冒充视觉验收**：必须在浏览器实际渲染、截图和点击；样式丢失、资源错位、字体失效即为失败。
8. **不把视觉选择当作发布授权**：默认内部预览；正式公开需要针对该具体成品再次确认资料、授权和发布范围。

# 第二章｜门店 DNA：从素材推导设计，而非从模板出发

### 2.1 建立六维门店画像

每个项目必须明确以下判断及证据来源：

1. **经营身份**：店名、品类、地域、门店数量、品牌成熟阶段、门店所在地的真实情况。
2. **产品结构**：招牌产品、原料/技法/口味、规格价格、菜单复杂度、食用方式。
3. **空间属性**：门头、装修、采光、席位、环境质地、动线、拍摄信息是否充分。
4. **客群与时段**：客群、到店目的（早餐/聚餐/夜宵/下午茶/商务/家庭）、消费价格带。
5. **文化资产**：老板经历、店名缘起、地方饮食语境、工艺故事、服务理念、现有 IP 与 VI。
6. **经营目标**：品牌识别、到店导航、套餐了解、电话联系、咨询、团购、会员引流等。

每一项都要标注：`已确认事实 / 待核实 / 设计假设`，不能把判断当事实。

### 2.2 证据层级与网页可用范围

| 级别 | 内容类别 | 举例 | 内部演示 | 正式公开 |
|---|---|---|---|---|
| F1 | 商家确认的事实/获授权素材 | 店名、菜单售价、老板确认的创立故事、照片 | 可 | 复核后可 |
| F2 | 经检索可核验的品类与地域知识 | 江湖菜文化、面食工艺的通用背景 | 可，附来源 | 审核来源和表述后可 |
| C1 | 原创设计与品牌建议 | Slogan、品牌世界观、IP 角色、页面文案 | 可，明确“概念” | 经商家确认采纳后可作品牌表达；不能虚构历史 |
| X1 | 临时占位及模拟经营数据 | 假地址、演示价、模拟团购 | 仅限醒目标注的内部原型 | 禁止 |

### 2.3 一店一气质的设计命题

最终必须形成一份可复核的 **Brand DNA Card（品牌 DNA 卡）**，至少包括：

- 一句话品牌定位、一个主文化命题、3 个品牌关键词、3 个禁止关键词。
- 最值得被看见的 1–2 个“证据主角”：真实招牌菜、门头、工艺动作或空间。
- 消费者最核心的三个问题与相应页面解答。
- 设计语言：版式骨架、色彩来源、主标题字、正文、摄影策略、材质、动效策略。
- 所有结论对应的素材 ID/商家说明/研究来源，以及不确定项。

**先有 DNA 卡，后有网页。** 如果证据不足，可做有限度的内部概念设计，但必须显示缺口与风险。

# 第三章｜文化系统：不是编故事，而是建立品牌意义

### 3.1 文化的五个可能入口

- **品牌自身**：可证实的创立动机、命名、经营者经历、真实待客方式。
- **料理本身**：原料选择、加工手法、口味结构、工艺时间、制作现场。
- **地方语境**：地域饮食习惯、城市生活方式、地方语言与器具（必要时查证）。
- **情境关系**：早餐的效率、朋友的围桌、家庭聚餐、独处咖啡、节日礼赠。
- **当代价值**：便利、品质、开放厨房、环保包装、产品创新等，必须有实际证据支撑具体承诺。

不强求所有门店拥有“历史”。新开烘焙店的文化可以来自一天的出炉节奏；社区小面馆可以来自切面、浇头与街坊关系；精品咖啡店可以来自风味标准和城市日常。

### 3.2 从文化主线推导全站元素

| 文化发现 | 必须转化的设计决策（可按店删改） |
|---|---|
| 店名语义与店主故事 | 首屏文案、语气、品牌标识与标题字形 |
| 地域或技法文化 | 版式修辞、视觉隐喻、章节命名、器物细节 |
| 招牌菜味觉结构 | 菜品详情分层、食物摄影近景、吃法建议 |
| 场景文化 | 页面动线、环境影像顺序、交互的顾客问题 |
| 待客与经营理念 | 门店讲述、服务说明、可执行 CTA |

**文化必须在视觉、交互、文案、信息组织中可感知，不准只增设一块“文化故事”长文。**

### 3.3 原创 IP 的适用边界

- 已有 IP：优先使用现有角色，核对版权、形象规范与用户授权。
- 尚无 IP：先判断品牌是否真正需要。若设计价值明确，可提出候选角色、人格、视觉结构、应用场景及禁用场景，标记“概念提案”。
- IP 不得抢夺招牌菜与品牌名称的识别层级，也不能用拟人角色代替真实食物照片。
- IP 的人物历史、年龄、创始关系不得编造成真实品牌档案。

### 3.4 内容写作的三层

**第一层：品牌句**（极短、准确、有辨识度）；**第二层：产品解释**（原料/风味/工艺、凭据与限制）；**第三层：顾客帮助**（第一次点什么、如何搭配、是否适合儿童或不吃辣人群，须以门店实际信息为依据）。

文字应该适配该品牌：夜宵可以直接有力，雅致中餐克制准确，手作面包更温和；不能一律“江湖”“烟火”“匠心”。

# 第四章｜视觉艺术指导：每个像素都有来由

### 4.1 设计决策八件套

每个网站都应为以下决定附上理由：`主视觉主体｜布局骨架｜色彩系统｜字体系统｜影像策略｜材质/点缀｜动效机制｜手机独立构图`。

**视觉证据优先级**：现有 Logo/VI → 店铺实拍与菜品色彩 → 文化与目标客群 → 创意隐喻。没有证据时不把火锅硬套“黑金”，不把中餐硬套“毛笔字”。

### 4.2 字体系统（强制逐店选型）

- **品牌主字/Logo**：保留经授权的现有标识；无现成品牌字时，才做字形方向或原创题字。
- **展示标题字**：可选书法、楷行、宋体、极黑、窄体、手写体、圆体等；必须对应文化/食材/消费场景。
- **章节标题**：建立阅读层级，可与展示字体形成反差，但必须可读。
- **正文/功能文字**：清楚、移动端可读，不能让繁复书法覆盖价格、电话、日期与优惠规则。
- **数字与辅助英文**：价格与营业信息的字体协调、单位和数字对齐，勿借英文字体冒充完整中文字体。

每次交付的《字体决策表》应包含：具体候选/来源/许可、应用场景、字重、字距、行高、中文覆盖、备用字体、实测截图。字体不因“以前用过”就自动复用。

### 4.3 定制书法字与透明 PNG/SVG/WebP

适用品类、品牌证据和设计目标吻合时，可单独设计手写/书法主标题，并作为网页视觉资产使用。

**制作规则**：

1. 优先保留真实招牌题字或已拥有的 Logo，不未经许可改造现有品牌字。
2. 校对字形、店名每个汉字及笔画辨识，不追求极端艺术化导致误读。
3. 交付透明底 PNG（建议按展示尺寸的 2×–3×制作），条件允许可另交 SVG/WebP；不要将整个网页文案都做成一张图。
4. 保留同等语义的 HTML 标题/可访问文本，必要时使用图像 `alt`，保障搜索、加载失败和屏幕阅读器可识别。
5. 在手机和桌面版分别检查文字与照片的遮挡关系、透明边、轮廓清晰度与暗/亮底兼容。
6. 记录字体/字形素材的来源与商用授权；第三方字体文件不得默认在交付包中任意再分发。

### 4.4 色彩与材质

每家店输出：主色、辅助色、强调色、背景色、文字色、交互反馈色；记录 HEX 和来源说明。色彩要呼应品牌 VI、实物照片、就餐场景；不要仅由菜系名称推定。通常控制视觉主色的数量，但有明确品牌规范时以 VI 优先。

点缀（印章、编号、纹理、笔触、网格、器具线描、地理符号）**必须能追溯到一个文化或产品含义**。不得无意义堆贴纸、粒子、假材质与装饰汉字。

### 4.5 摄影与图像处理

- 菜品保留**食材 DNA**：主体、器皿、份量、颜色、重要食材可辨识，不自行添加并冒充真实配料。
- 主锅、主盘、包装 Logo 和门头招牌进入安全区；避免意外裁切，不能拉伸变形。
- 针对不同屏宽分别构图，可用同一素材的不同安全裁切，但不能简单把桌面封面缩小。
- 影像必须有层次：前景主角、中景用餐/器物、后景空间/材质；虚实变化服务叙事。
- 不能以人工生成的豪华门店当作店铺实拍。内部演示可用明确标记的概念资产，正式上线必须替换或由商家认可作为艺术性非实景视觉。

### 4.6 动效与 UI/UX

动效遵循品类逻辑：锅物可用轻蒸汽，饮品可用局部光泽，烘焙可用纸张翻揭，咖啡可用克制的节奏切换。**一个页面原则上只设一个主导动效语言**，其余是操作反馈。

- 微交互推荐 150–250ms、章节揭幕 400–700ms，均为待实测的起始预算。
- 全部交互支持触屏与键盘，不把 hover 当唯一入口；不锁死滚动。
- `prefers-reduced-motion` 适配必须存在；动画关闭后功能和信息不丢失。
- CTA 始终清晰可点，主动作优先，手机固定高频操作建议不超过 3 个。

# 第五章｜品类适配：规则自适应，不是品类模板

以下是**设计判断参考**，不是硬编码配色、字体或区块。每一家仍须回到其实际资料与 VI。

| 品类 | 可研究的文化核心 | 候选视觉语法 | 优先考虑的有用交互 | 易犯错误 |
|---|---|---|---|---|
| 川渝锅物、砂锅、肥肠鸡 | 食材组合、锅气、地域饮食、围桌社交 | 大锅纵深、标题与锅体的空间关系、浓淡对照 | 人数/辣度/配菜及吃法建议 | 全屏假火焰、捏造江湖传承 |
| 烧烤夜宵 | 炭火工序、夜间社交、串品结构 | 斜向节奏、炉火局部、紧凑排版 | 串品分类、组合、营业时间 | 重特效遮挡菜价 |
| 手擀面、米线、小吃 | 制面、汤底、浇头、街巷生活 | 碗与文字透视、质朴材质、工艺细节 | 浇头、辣度、汤底、搭配 | 餐具裁切、假老字号 |
| 烘焙与甜品 | 发酵、时间、原料、日常仪式 | 包装编辑、柔和近景、留白、切面 | 口味/原料/储存建议（需证据） | 每家都做米白奶油模板 |
| 精品咖啡 | 风味、烘焙理念、萃取与空间 | 现代编辑分栏、节奏留白、器具摄影 | 豆种/风味/冷热/空间浏览 | 伪造产区、奖项 |
| 茶饮与冰品 | 茶底、果味、季节性、清凉触感 | 杯体纵向、高光、清透材质 | 甜度/冰度/茶底、过敏信息（如有） | 透明特效覆盖功能字 |
| 披萨与西式小食 | 烘烤工艺、分享、原料 | 圆盘与排版错位、食物切面、编辑感 | 尺寸/口味/份数建议 | 未核实芝士与食材宣称 |
| 宴席与中式正餐 | 待客礼序、空间、菜序与聚会目的 | 空间叙事、端庄字阶、器皿与环境 | 包间/人数/套餐/咨询 | 虚构高档装修与星级 |

**拒绝模板化的检查方法**：把当前方案的店名和图片替换成另一家不同品类的店，若仍显得“差不多合理”，说明文化与视觉推导不够深，必须重新设计。

# 第六章｜一体化网页的信息架构与转化逻辑

### 6.1 推荐叙事路径（非固定模块顺序）

`品牌识别与主张 → 食物与品类文化 → 招牌产品解释 → 情境化交互与顾客建议 → 门店空间/待客方式 → 菜单详情与联系到店`

某些便利性高的品类，应在首屏直接给菜单入口；高客单宴席需要更快的包间咨询；夜宵更强调营业时间。**模块多少、先后顺序与表现形式依据客户需要重新决策。**

### 6.2 产品详情至少覆盖的字段

真实菜名、图片、价格与单位/规格、主要风味；有依据时增加原料、技法、推荐搭配、适用人数、上新/停售状态、重要使用提示。缺失信息不得暗示已核实；可在内部原型中提示“需商家补充”，公开时合理隐藏。

### 6.3 顾客建议的可信边界

建议可以基于真实菜单生成，但推荐人数、份量、加价、套餐、辣度等必须与实际产品规则相匹配。AI 可做搭配建议，不应把缺证据的热量、过敏原、儿童适宜性、食材产地编造成确定结论。对于此类敏感信息，优先使用商家确认的说明。

### 6.4 商家 CTA 和技术能力边界

首版网页聚焦展示、联系、到店与已有权益入口；不默认接管点餐、收银和团购券交易。`tel:` 使用核实电话号码；导航使用商家确认的地图坐标或真实 URL；团购、企业微信和会员使用真实官方入口。模拟“预订成功”仅可作为内部演示状态且必须明显注明不产生真实预订。

# 第七章｜交付质量：不可绕过的验收闸门

### 7.1 必须通过的五道门槛

1. **真实门槛**：网页事实可溯源；原创概念和占位明确标注；素材权利及公开许可可追踪。
2. **文化与视觉门槛**：品牌主张能从具体资料推导；标题、图像、色彩、布局有品类与门店依据；没有通用模板感。
3. **交互门槛**：重要操作有实际反馈；交互建议基于明确数据；无假外链、伪付款、伪预约确认。
4. **展示门槛**：用户能够快速识别店名/品类/招牌；真实地址、营业时间、联系方式、价格等有资料时可轻松找到。
5. **工程门槛**：真实浏览器渲染；样式与资源不丢失；手机桌面分辨率、点击和性能做实测；给出失败/未测清单。

任何一道关键门槛失败，不得标为“已可正式交付”。主观审美必须经过用户设计验收，不可由自动测试代替。

### 7.2 建议的数值化测试基准（均须实测并记录）

| 项目 | 设计/测试基准 |
|---|---|
| 屏宽 | 至少 360 / 390 / 768 / 1440px；无非预期横向溢出 |
| 手机触控目标 | 关键操作区域目标 ≥ 44×44 CSS px |
| 字号可读性 | 正文以 16px 左右为起点，说明一般不低于 12px，按实际字体视觉验收 |
| 文本对比度 | 以 WCAG AA 为目标：普通文字 ≥ 4.5:1；大字 ≥ 3:1 |
| 动效 | 支持减少动效；退出视口和后台暂停持续动画；不阻塞点击 |
| 性能 | 首屏静态资源初始预算建议约 1.5 MB；按真实素材可调整，并记录实测 LCP/CLS/INP |
| 素材 | 菜品/锅/盘完整、无变形；Logo 与重要门店文字不误切 |
| 交付 | HTML/CSS/JS 和素材完整；独立 HTML 或正确目录 ZIP；至少电脑/手机实渲染截图 |
| 兼容 | 微信/抖音内置浏览器、地图/电话/券跨 App 入口须按实际场景真机验证；未测明确写未测 |

### 7.3 复盘：已发生过的失败类型必须永久回归测试

- `HTML 只有白底蓝链` → CSS/JS 未随文件加载：交付前必须单独打开最终交付路径进行验证。
- `手机端主视觉消失` → 容器在窄屏下宽度或高度坍缩：必须检查实际盒模型、图像显示与裁切。
- `以演示图冒充门店实拍` → 演示图注明“非真实门店”，正式发布前换图或获确认作为艺术性画面。
- `页面有按钮却无作用` → 所有可点击元素逐项列成测试用例，包括打开/关闭/切换/反馈和失败态。
- `把规范包当成成品` → 文档、Schema、HTML 工程、实际部署是不同状态，不得混称完成。

# 第八章｜工作方式、职责与版本治理

### 8.1 谁负责什么

- **用户/采集人员**：拍照、取得商家基础信息、确认需求、交付素材包、收集反馈。
- **餐饮商家**：确认品牌事实、菜单价格、经营信息、授权素材、可公开的真实入口及最终页面内容。
- **设计智能体**：盘点资产、判断事实层级、研究文化、制定品牌 DNA/视觉系统/交互方案、生成网页和验收文档。
- **开发与发布方**：实现必要的后端/部署、校验实际外链、托管和移动端环境，保护密钥与数据。
- **验收方**：明确区分“设计通过”“功能通过”“资料通过”“上线通过”。

### 8.2 版本与变更

- 每次设计记录：商家素材包版本、研究日期、已确认事实版本、设计稿版本、网页构建版本、测试结果与发布状态。
- 可调整组件库，但**一店一文化、一店一视觉**不能被组件复用破坏。
- 字体、价格、营业时间、优惠有效期、门店照片变更后应触发相应重新验收。
- 任何新经验只能作为“候选判断规则”，不能悄悄覆盖已经由用户认可的总原则。

### 8.3 成功判定

正式成功不是“生成了一个链接”，而是：**品牌有出处，视觉有辨识度，交互有价值，信息有依据，网页经实测，商家认可，顾客可正常使用。**
